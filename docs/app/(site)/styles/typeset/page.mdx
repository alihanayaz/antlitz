# Typeset

A stylesheet for long-form content — markdown, MDX, a CMS rich-text field.

The components in this package cover authored markup, where you control the
JSX. Typeset covers the other half: content rendered from data, where every
node arrives as a plain element and there is nothing to wrap.

## Installation

Import it after the theme, then wrap the rendered output.

```css
@import "tailwindcss";
@import "antlitz/theme.css";
@import "antlitz/typeset.css";
```

```tsx
<div className="typeset">{renderedContent}</div>
```

## Usage

Headings map onto the `Heading` component's scale — `h1` through `h4` become
`lg` through `xs` — so a rendered `<h2>` and an authored `<Heading size="md">`
are the same size on the same page.

## Rhythm

Three variables set the reading rhythm; everything else derives from the
theme's tokens.

| Variable            | Default             | Role                 |
| ------------------- | ------------------- | -------------------- |
| `--typeset-size`    | `--text-base`       | Base text size       |
| `--typeset-leading` | `--leading-relaxed` | Line height          |
| `--typeset-flow`    | `1.5em`             | Space between blocks |

`--typeset-flow` is in `em`, so it resolves against each block's own size: a
heading opens more room above itself than a paragraph does, from one
declaration rather than a table of margins.

Spacing only ever comes from the start edge — a block is spaced by what
precedes it, never by what follows — so appending to streamed content never
restyles what is already on screen.

## Overriding

Typeset sits in the `components` cascade layer with every element selector
wrapped in `:where()`, so its specificity is exactly `.typeset`. Any Tailwind
utility beats it without `!important`.

```tsx
<div className="typeset [&_blockquote]:border-s-4">
```

To change the rhythm instead, set the variables.

```tsx
<div className="typeset [--typeset-flow:1.25em]">
```

## Opting out

<Preview file="typeset" name="OptOut" isolate={false} />

`not-typeset` — or `data-not-typeset` — reverts everything Typeset applied
within a subtree, so components rendered inside prose keep their own styling.

It uses `revert-layer`, which undoes the `components` layer and leaves later
layers intact. Utilities still apply. A consumer's own `@layer components`
rules are reverted there too, which is worth knowing if you keep raw component
CSS in that layer.

## Not a component

Typeset has no props and no import from the package root. It is a stylesheet
you apply with a class, which is why it can style markup generated by a
renderer you do not control.

The boundary: Typeset owns anything purely typographic; components exist where
there is behaviour or an API worth having.
